# Correctly V7.1.2 — Area selection and capture

**Parent spec:** `v7/v7.1.md` (read §0 and §15 first). **Part 2 of 4.**
Independent of V7.1.1 (either order).
**Status:** PLAN — NOT PROOF OF IMPLEMENTATION. Rename to `v7.1.2_done.md`
only when delivered.

## 1. Goal

The page can let the user draw a rectangle, and the worker can turn
"rectangle + viewport" into a cropped, bounded image of the visible tab.
**No provider call, no message wired to the window yet, nothing visible to
the user in normal use.**

## 2. Scope

- `content/area.ts` (bundled where the modal lives: `content.js` and
  `smart.js` — check how `modal.ts` is bundled):
  - `selectArea(doc): Promise<{ rect, viewport } | null>` — full-viewport
    overlay, closed shadow root, highest z-index, crosshair, dim outside the
    rectangle, size label, hint bar (fr/en via `content/messages.ts`);
  - pointer events (mouse + pen + touch via Pointer Events, pointer capture);
    drag in any direction; release = confirm; Esc / right click / `blur` /
    `visibilitychange` = cancel (`null`);
  - page scroll blocked while selecting (restored after); page keyboard
    events isolated like the modal (`ISOLATED_EVENTS` pattern);
  - removes itself and every listener in all cases (including errors);
  - pure helpers: `normalizeRect(start, end)`, `clampRect(rect, viewport)`,
    `isLargeEnough(rect)` (≥ 8 × 8 CSS px).
- `background/capture.ts`:
  - `cropScale(bitmapSize, rect, viewport, maxLongSide)` (pure): scale =
    `bitmap.width / viewport.width`, crop in device pixels, clamped, output
    size with long side ≤ D8, upscale ≤ 2×;
  - `captureArea(tab, rect, viewport, deps)`: checks the tab is active in
    its window, `chrome.tabs.captureVisibleTab(windowId, { format: 'png' })`,
    `createImageBitmap`, `OffscreenCanvas` crop/scale, `convertToBlob` PNG,
    JPEG 0.9 if above the size budget, base64; Chrome errors →
    `CAPTURE_FORBIDDEN` (restricted page) or `CAPTURE_FAILED`; never retried;
    every dependency injectable for tests (no real Chrome in Vitest).
- Hide/show helpers for Correctly's own UI (window, handle, selection
  button): a single function used by part 3, waiting two animation frames
  after hiding.

## 3. Out of scope

`EXTRACT_TEXT` message, controller, provider call, window button, consent,
settings. A temporary debug trigger is **not** allowed in `frontend/src`.

## 4. Tests

O6–O8 (`v7.1.md` §10), plus:

- geometry table: zoom 100/150 %, DPR 1, 1.25, 2, rect at the edges,
  negative drag, rect larger than viewport;
- `captureArea` with fakes: inactive tab → `CAPTURE_FAILED`, Chrome error
  "cannot be captured" → `CAPTURE_FORBIDDEN`, output image size equals the
  computed crop, JPEG fallback above the budget;
- overlay: jsdom pointer sequence → rect; cancel paths → `null`; after
  resolve, no node and no listener left (count `addEventListener` /
  `removeEventListener`); scroll restored.

## 5. Pitfalls specific to this part

- jsdom has no `OffscreenCanvas` / `createImageBitmap`: keep them behind
  injected dependencies; test the pure maths separately.
- Pointer capture: release it on every exit path, or the page keeps the
  pointer.
- Do not use `devicePixelRatio` for the crop (pitfall 5).
- The overlay must not be in the screenshot: the hide helper is tested to
  remove it **before** resolving.
- No new permission: if you feel one is needed, stop and report.
