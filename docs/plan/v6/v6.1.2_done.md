# Correctly V6.1.2 — API engine and accounting

**Parent spec:** `v6/v6.1.md`. **Part 2 of 4.** Requires V6.1.1.
**Status:** DELIVERED (tests R5–R7, migrations, build).

## 1. Goal

A check can be sent to the user's own Gemini/OpenAI key through the worker,
with its own route, limits and statistics. Still **no visible underline**:
the feature is exercised by tests and a stub.

## 2. Scope

- **WP3 API engine:**
  - message `correctly.v5.checkText` → `{ text, context }`, exact-shape
    guard, ≤ 1,000 code points; answered with `{ ok, issues[] }`;
  - worker task kind `realtime` in `connection-controller.ts`: route slot
    `realtime` (inherits Default unless set), short timeout (8 s), **no
    retry**, low output budget, minimal reasoning, result validated with the
    V6.1.1 validator;
  - V5.8 limits and V5.9 statistics for `realtime` (own default limit, e.g.
    500/day; IndexedDB schema bump with migration and tests if needed);
  - pause when the limit is reached; on-demand actions unaffected unless the
    total limit is reached.
- **Data model** (`v6.1.md` §5): `triggers.realtime` (default false, not
  synced), `realtime` settings `{ engine, apiConsent, disabledSites }`
  normalized; route slot `realtime` in `shared/providers.ts` /
  `shared/models.ts`. `apiConsent` stays false until V6.1.3 adds the dialog.
- Sender-trust rules unchanged: only trusted contexts, exact message shape.

## 3. Out of scope

Overlay, card, settings page, local engine, dictionary.

## 4. Tests

`apiConsent`, sentence + one previous only), R7 (guard, route, task counted,
