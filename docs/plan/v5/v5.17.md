## 1. Product decision and acceptance contract

### 1.1 Mission

The 5.14 sync (`chrome.storage.sync`) is erased by Chrome when the
extension is removed, and is tied to the browser profile. 5.17 lets **any
user** sign in with their Google account in Correctly's settings and keep
their data in the cloud: removing the extension, reinstalling it or
changing computer, they sign in again and get everything back.

### 1.2 New V5.17 functionality

- **Settings → Account** (replaces Settings → Sync): "Sign in with Google",
  the signed-in email, "Back up now", "Restore", "Sign out", "Delete my
  account and my cloud data".
- **Backed up** (each domain opt-in, all on by default after sign-in):
  - `settings` — rewrite, translation (favorites, variants), interface
    language, keyboard and right-click triggers (same subset as 5.14
    `pickSettings`);
  - `shortcuts` — text shortcuts (three-way merge per shortcut, 5.14 rules);
  - `keybindings` — Correctly's own keyboard shortcuts;
  - `keys` — API key profiles, routes and keys, **always encrypted on the
    computer with the user's passphrase** (5.14 PBKDF2-SHA-256 600,000 →
    AES-GCM). Neither the owner, Google nor Firebase can read them.
- **Restore after reinstall:** sign in → settings, shortcuts and keyboard
  shortcuts come back at once; the passphrase brings the keys back.
- **Works without an account.** Signing in is optional; everything keeps
  working locally as in 5.16.
- English and French interface.

### 1.3 Non-goals

- No server, API, function or hosting of our own (no Cloud Functions, no
  Next/Nest/Express). No Firebase Hosting.
- No other sign-in method than Google (no email/password, no anonymous).
- No sharing between users, no admin view, no analytics, no ads.
- Usage limits and statistics stay local (see D3).
- No change to the AI requests (still one request per explicit action, sent
  by the worker straight to Gemini/OpenAI; Firebase never sees user text).

### 1.4 Required examples

| Situation                                                    | Expected                                                                          |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| New computer, fresh install, sign in                         | settings, shortcuts, keyboard shortcuts restored; keys after the passphrase       |
| Remove the extension, reinstall, sign in                     | same as above; nothing lost                                                       |
| Change a setting while signed in                             | backed up within a few seconds (debounced), one write per domain                  |
| Two computers edit different shortcuts                       | both kept (merge per shortcut)                                                    |
| Forgotten passphrase                                         | keys cannot be restored (stated clearly); "Reset keys backup" re-encrypts local keys with a new passphrase; other domains unaffected |
| Offline                                                      | local work continues; backup retried at the next change or settings opening       |
| "Delete my account"                                          | confirmation, then all cloud documents and the Firebase account deleted; local data kept |
| Not signed in                                                | zero request to Firebase/Google                                                   |

## 4. Architecture

```text
settings page ──message──► service worker ──fetch──► identitytoolkit / securetoken / firestore.googleapis.com
                                  │
                                  └─ chrome.identity.launchWebAuthFlow ──► accounts.google.com (Google's own window)
```

- **No Firebase SDK** (no new dependency, smaller bundle, no remote code):
  the worker calls the documented **REST APIs** with `fetch`, using the
  existing transport rules (`credentials:'omit'`, `redirect:'error'`,
  timeout, no automatic retry, provider text never shown).
- **The worker stays the only network caller**, and the only reader of the
  Firebase tokens.
- **Sign-in (Chrome and Brave):** `chrome.identity.launchWebAuthFlow` on
  Google's OAuth endpoint (`response_type=id_token`, scopes
  `openid email profile`, random `nonce` checked in the returned token,
  redirect `https://<extension-id>.chromiumapp.org/`), then
  `accounts:signInWithIdp` (Identity Toolkit) with the Firebase web API key
  → Firebase ID token (1 h) + refresh token. `getAuthToken` is **not** used
  (Chrome only, not Brave).
- **Refresh:** `securetoken.googleapis.com/v1/token` with the refresh token
  when the ID token is within 5 min of expiry.
- **Data:** Firestore REST
  `projects/{projectId}/databases/(default)/documents/users/{uid}/data/{domain}`,
  one document per domain: `{ schema: 1, rev, updatedAt, payload }` where
  `payload` is the canonical JSON string of the 5.14 domain format (`keys`:
  the encrypted envelope only). Writes use `currentDocument.updateTime`
  preconditions (optimistic concurrency): on conflict, re-read, merge
  (shortcuts) or keep the newest (other domains, with the replaced version
  saved to the existing backup slot), write again — at most once per
  attempt, then report.
- **Configuration:** `frontend/src/shared/cloud-config.ts` (versioned):
  `apiKey`, `projectId`, `oauthClientId`. These are **public identifiers**,
  not secrets; security comes from the Firestore rules and Google sign-in.
  Missing config → the Account page says "not configured", zero request.

## 5. Data model and storage

- `storage.local` (worker writes only, trusted contexts read):
  - `correctly.v5.cloudSession` — `{ uid, email, refreshToken, idToken,
    expiresAt }`. Sensitive: never logged, never sent to a page script,
    removed on sign-out and account deletion.
  - `correctly.v5.cloudPrefs` — domains on/off (per computer).
  - `correctly.v5.cloudState` — last `rev`/`updateTime` per domain, last
    success/error code per domain.
- Firestore: `users/{uid}/data/{settings|shortcuts|keybindings|keys}` only.
- Every read passes through `normalize*`; corrupt or oversized cloud data is
  never applied (5.14 rule "never a silent loss").

## 6. Security

- **Firestore rules** (versioned in `firebase/firestore.rules`, pasted by
  the owner in the console):
  ```
  rules_version = '2';
  service cloud.firestore {
    match /databases/{db}/documents {
      match /users/{uid}/data/{domain} {
        allow read, delete: if request.auth != null && request.auth.uid == uid;
        allow create, update: if request.auth != null
          && request.auth.uid == uid
          && domain in ['settings', 'shortcuts', 'keybindings', 'keys']
          && request.resource.data.keys().hasOnly(['schema', 'rev', 'updatedAt', 'payload'])
          && request.resource.data.payload is string
          && request.resource.data.payload.size() <= 200000;
      }
      match /{document=**} { allow read, write: if false; }
    }
  }
  ```
- API key restricted (by the owner) to Identity Toolkit, Token Service and
  Cloud Firestore APIs. Only the Google provider enabled.
- Manifest: permission `identity`; hosts
  `https://identitytoolkit.googleapis.com/*`,
  `https://securetoken.googleapis.com/*`,
  `https://firestore.googleapis.com/*`; same three in CSP `connect-src`.
  `audit-dist.mjs` updated to require exactly these, and still refuses
  anything else (localhost, other hosts, `.pem`, private keys, client
  secrets: pattern `GOCSPX-`).
- Messages: new constants in `shared/contracts.ts`, exact-shape guards,
  accepted **only from the settings page**; replies rebuilt field by field;
  tokens never leave the worker.
- No log. The user's AI text never goes to Firebase.
- Account deletion: delete the four documents, then
  `accounts:delete` (Identity Toolkit), then local session removal.

## 7. Limits, statistics and sync

- Limits and statistics: unchanged and local (D3).
- Firebase calls are **not** AI requests: not counted in limits/statistics.
- Free Spark plan: 50,000 reads / 20,000 writes / day for all users;
  debounce (D6) keeps a user well under 100 writes a day.
- D1 = replace: the Sync page disappears; on first sign-in, if 5.14 sync
  data exists locally, offer "Upload this computer's data". `storage.sync`
  is cleared only after a successful upload and an explicit confirmation.

## 13. Risks

| Risk                                          | Mitigation                                                                 |
| --------------------------------------------- | -------------------------------------------------------------------------- |
| Firebase config copied by someone else        | rules per uid, size limits, Google-only sign-in, Spark plan (no bill)      |
| Refresh token stolen from the local profile   | stored like API keys (trusted contexts only); sign-out revokes locally     |
| Owner loses access to the Firebase project    | 2-step verification on the owner account; local data always kept          |
| Forgotten passphrase                          | stated before setting it; keys reset flow; other domains unaffected        |
| Quota exhausted (many users)                  | debounce; error `CLOUD_*` shown, local work unaffected; upgrade is the owner's choice |
| Consent screen in "testing" mode              | only listed test users can sign in until published (D5)                    |
