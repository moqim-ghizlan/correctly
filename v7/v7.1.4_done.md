# Correctly V7.1.4 — Security review, docs and release

**Parent spec:** `v7/v7.1.md` (read §0, §12 and §15 first). **Part 4 of 4.**
Requires V7.1.3.
**Status:** PLAN — NOT PROOF OF IMPLEMENTATION. Rename to `v7.1.4_done.md`
only when delivered.

## 1. Goal

Ship the whole V7.1 milestone: reviewed, documented, versioned per **D0**,
packaged, website updated, honestly tested. Follow
`docs/general/processus.md` and the `correctly-release` skill.

## 2. Scope

1. **Security review** (skill `correctly-security`) → `docs/v7.1/SECURITY.md`:
   new message and sender rules, screenshot never in the page, image never
   stored/synced/logged, no new permission/host, consent, prompt injection,
   audit of `dist/` (`scripts/audit-dist.mjs`, add a rule if useful).
2. **Docs** `docs/v7.1/`: `ARCHITECTURE.md`, `RELEASE_NOTES.md`,
   `TEST_REPORT.md` (all parts), `MANUAL_TEST_CHECKLIST.md` (`v7.1.md` §11).
3. **Full regression:** format, lint, typecheck, tests, build, audit,
   browser smoke test.
4. **Manual checklist with the owner** (real key, Chrome and Brave): results
   PASS / FAIL / NOT TESTED / BLOCKED; real cost per image from statistics in
   the release notes.
5. **Version** per D0 (`processus.md` §3):
   - `npm version X.Y.0 --no-git-tag-version`;
   - `frontend/manifest.json` (`version`, `version_name`, `name`,
     `description`); `scripts/audit-dist.mjs`; `scripts/package.mjs`;
     `scripts/verify-browser.mjs`;
   - settings-page version texts in `scripts/i18n-options.mjs`, then
     `node scripts/i18n-options.mjs` and `npm run format`;
   - `CLAUDE.md` ("État actuel", carte du dépôt: new files); `README.md`;
   - search the old version string everywhere to miss nothing, then re-run
     step 3.
6. **Package:** `npm run package` → check the zip's `manifest.json` version
   and the `.sha256`.
7. **Website** (minor or major only — `processus.md` §5): zip in
   `website/assets/download/` (old one removed), `site.js`, `fr.js` **and**
   `en.js` (same keys: `dl.*`, `footer.version`, "Nouveauté", Features, FAQ
   cost/DRM/fullscreen), `index.html` `release-num`,
   `website/scripts/verify.mjs`, **`website/privacy.html`** (image of the
   selected area sent to the chosen provider, nothing kept); then in
   `website/`: `npm run build`, `npm run verify` (must end with "0 FAIL");
   at the root: `npx prettier --write website`.
8. **Video:** only if D0 = major (`7.0.0`): `video-brag/SETUP.md` in full,
   in the same task, then report it in `website/`. For a minor: **no video**.

## 3. Out of scope

Any new feature or behaviour change (bugs found here are fixed minimally and
noted in the release notes).

## 4. Tests

Full O1–O15 matrix as regression + manual checklist. The live part is
**BLOCKED** until the owner runs it with their key — never written as PASS.

## 5. Pitfalls specific to this part

- Version string forgotten in one file → search the previous version text.
- `website/site/` is generated: never edit it by hand; commit it with
  `website/` for a minor/major.
- The site must not announce OCR unless the offered zip contains it.
- Privacy text forgotten → the site would hide that images are sent.
- The zip name holds only `x.y`: check the right file is copied.
- Do not tag before the owner has seen the test report.

## 6. Delivery (only on the owner's explicit request)

1. One commit on `dev`: code + docs + `website/` + `website/site/`
   (`feat: text from a screen area (V7.1)` + attribution line).
2. Annotated tag `vX.Y.0` on that commit.
3. Push `dev` and the tag; follow the GitHub Pages deploy (Actions).
4. Never merge into `main` without a request.

## 7. Definition of Done

- [ ] Security review, docs, `CLAUDE.md`, `README.md`.
- [ ] Format, lint, typecheck, test, build, audit, smoke test passing.
- [ ] Manual checklist with honest results.
- [ ] Version, package, website (video if major) updated and verified.
- [ ] This file renamed `v7.1.4_done.md`; `v7.1.md` renamed `v7.1_done.md`.
- [ ] Commit, tag, push only on the owner's explicit request.
